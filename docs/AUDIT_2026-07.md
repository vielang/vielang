# VieLang — Project Audit + Post-MVP Upgrade Roadmap

**Date:** 2026-07-02
**Scope:** End of Phase 8 — student journey + tutor ops + admin ops + reviews + materials all live against real Supabase. Docker LiveKit stack running locally; production deploy (P9–P10) still to come.
**Purpose:** Take stock of what's in the codebase, call out what's still amateur-hour, and lay out the phases that turn this from an MVP into a product that scales, ships safely, and doesn't wake you up at 3am.

---

## 1. Executive summary

**What works**

- End-to-end product loop is closed: sign in → discover tutors → book → LiveKit video → review → materials. Everything runs against real data.
- Next.js 16 App Router with Server Components as the default; API routes are thin and mostly zod-validated.
- Supabase schema is well-shaped: FKs everywhere, enum CHECKs, DB-side trigger keeps rating in sync.
- LiveKit is fully self-hosted, keys match on both sides, JWT validates against the server.

**What's still MVP-flavored**

The list is honest but not scary. Nothing here is a "your app is broken" — the app runs. But shipping to real users invites:

1. Design language still smells of the golf pivot (green + gold, "VINAROUNDING" typography holdovers).
2. Zero automated tests. Every regression is caught by hand.
3. No rate limiting, no CSP, no HTML sanitization on user text, no CSRF token on mutations.
4. No observability — errors go into `console.error` and die.
5. No email or SMS for booking lifecycle events.
6. Admin/tutor list endpoints return everything unpaginated.
7. Timezone hardcoded UTC+7 in the booking engine — a student booking from Seoul sees VN times mislabeled.
8. Docker stack is dev-only; no Caddy/HTTPS/prod webhook secret yet.

Any single item on that list is 1–2 days of focused work. This doc groups them into phases (§6) so you can pick them off in order.

## 2. Design system audit

### 2.1 Current tokens

| Token                   | Value                                                                  | Where                              |
| ----------------------- | ---------------------------------------------------------------------- | ---------------------------------- |
| `--color-forest-green`  | `#0A2F28` (very dark green)                                            | primary + brand accents            |
| `--color-metallic-gold` | `#C5A059`                                                              | badges, hover, dark-mode brand ink |
| `--color-primary`       | `oklch(0.27 0.04 168)` (forest green)                                  | shadcn button/etc                  |
| `--color-accent`        | `oklch(0.72 0.10 80)` (metallic gold)                                  | shadcn accent                      |
| `--radius`              | `0.75rem`                                                              | shadcn base                        |
| Fonts                   | `Inter` (sans), `Playfair Display` (serif), plus Nanum Gothic/Myeongjo | KR-legacy fonts still loading      |

**Findings**

- **Palette is golf legacy.** Forest-green + metallic-gold reads like a country-club emblem. Fine for VinaRounding; wrong for an edtech brand targeting Vietnamese students learning English.
- **Dark theme is over-tinted.** Slate-blue background with green-shifted accents. Fine, but combined with the golf palette it feels dated.
- **171 occurrences** of `forest-green` / `metallic-gold` across 48 files. Any recolor needs to replace both the CSS variables AND rename the Tailwind class names for the code to stay semantic.
- **KR fonts still preloaded.** `Nanum Gothic` + `Nanum Myeongjo` load on every page because layout.tsx still asks Google Fonts for them. VN + EN don't need them.
- **Typography inconsistent.** Some headings `font-serif` (Playfair), most `font-sans`. Serif for hero + section headings works; for KPI cards it's random.
- **No spacing scale documented.** shadcn `--radius` is defined but semantic spacing isn't.

### 2.2 Proposed new palette

**Recommendation: Indigo + Amber**

Chosen for: education-adjacent trust (Preply, Notion, Linear all skew indigo/violet), high WCAG AA contrast on both light and dark, distinctive from Duolingo (green), Cambly (light blue), iTalki (red-orange).

| Role            | Class name                       | Hex                    | Notes                                       |
| --------------- | -------------------------------- | ---------------------- | ------------------------------------------- |
| Primary (light) | `brand`                          | `#4F46E5` (indigo-600) | CTAs, headers, active states, links         |
| Primary (dark)  | `brand`                          | `#818CF8` (indigo-400) | brighter to hold on dark background         |
| Accent          | `accent-warm`                    | `#F59E0B` (amber-500)  | "featured" pills, hover highlights, ratings |
| Success         | Tailwind `emerald-500`           | `#10B981`              | booking confirmed, review submitted         |
| Warning         | Tailwind `amber-500`             | already accent         | pending, expiring                           |
| Danger          | Tailwind `red-500`               | `#EF4444`              | cancel, error banners                       |
| Neutral         | Tailwind `slate` scale           | —                      | background + text                           |
| Surface (light) | `bg-white` + `slate-50` gradient | —                      | app background                              |
| Surface (dark)  | slate-950 base w/ indigo-tinted  | —                      | keep the tinted-slate approach, retint      |

**Rename plan**

- `forest-green` → `brand`
- `metallic-gold` → `accent-warm`

That's a Tailwind class rename in one bulk pass. No CSS variable rename inside shadcn (`--primary`, `--accent`) — those stay, we only shift their OKLCH values.

### 2.3 Alternative palettes (if you dislike indigo)

| Style                 | Primary              | Accent                | Feels like                                   |
| --------------------- | -------------------- | --------------------- | -------------------------------------------- |
| **Violet + Coral**    | `#7C3AED` violet-600 | `#F97316` orange-500  | Skillshare, energetic, younger audience      |
| **Slate + Emerald**   | `#0F172A` slate-900  | `#10B981` emerald-500 | Notion/Linear, ultra-professional, less warm |
| **Deep Teal + Coral** | `#0F766E` teal-700   | `#FB7185` rose-400    | Duolingo-adjacent but distinct, playful      |

Any of these can be swapped in by changing 6 CSS variable values.

## 3. Frontend / UX gaps

### 3.1 Layout

- **Header**: Language switcher still lists KR alongside VN/EN even though roadmap targets VN+EN. Wordmark hard-codes uppercase VIELANG in a serif; brand should live in a shared component with logo lockup.
- **Footer**: Uses `SiteSettingsContext` defaults which are mostly empty (address, phone, socials all blank). Legal-compliance fields (business registration number, mail-order sales number) are golf/Toss-payments legacy — remove until payments actually land.
- **MainShell**: `ChatWidget` is still in-tree and renders on every route. It only makes sense once we have real support. Gate behind a flag.

### 3.2 Home

- Categories row uses emoji icons (🎯 💼 🎈…) — reads amateur. Replace with Lucide icons matching the brand.
- No testimonials section (roadmap §3.1 listed it) — deferred but should return once we have real reviews.
- No news preview on home despite `/news` being deep-linked.
- Hero CTA ("Find a Tutor") lacks a secondary "Become a tutor" affordance — currently there's no signup-as-tutor flow at all.

### 3.3 Tutor discovery

- `/tutors` filter bar only exposes specialty + sort. Missing: level (A1–C2), price slider, rating floor, language spoken.
- Tutor cards omit tutor's timezone / next-available slot — students book blind on the timing side.
- No favorite / bookmark. No "Compare tutors" side-by-side. Both post-MVP.
- Tutor detail page: no share button, no report/flag button.

### 3.4 Booking

- 4-step dialog reads clean, but no progress indicator (1/4, 2/4…).
- Date picker is a plain grid — nice enough, but no month navigation. Only shows dates with slots in the next 14 days.
- After picking a time, back button returns to the date step but re-fetches slots. Cache them.
- On 409 slot_taken, we refetch and reset to time step but don't preserve which date was picked.
- No confirmation of tutor's timezone next to the slot — students in KR/JP will misread.

### 3.5 Sessions

- `SessionCard` action row wraps awkwardly on mobile when Join + Materials + Review + Cancel all appear. Collapse into a "more" menu at narrow widths.
- No countdown for imminent sessions ("starts in 4 min").
- Review dialog star picker jumps in size on hover — the +10% scale is jarring. Use color state change only.
- No reschedule UI even though the API supports it (`PATCH { action: 'reschedule' }`).

### 3.6 Video room

- `<LiveKitRoom>` prefab is fine but has no in-room UI beyond the default `VideoConference`. No custom control for "raise hand", no session-ended screen with review CTA.
- Disconnect fires `/my-sessions` navigate — ideally show a "how did it go?" mini-modal first.

### 3.7 Admin

- Overview KPIs + chart look right, but sessions/users tables have no pagination — will fall over past 200 rows.
- No export (XLSX) — the `xlsx` package is still in `package.json` from the golf era but unused. Either use it or drop it.
- Tutor approval only exposes approve/reject. No "request more info" state, no message to applicant.
- Users role dropdown lets admin demote themselves — server blocks it but UI doesn't gray out the option.

### 3.8 Tutor dashboard

- Availability editor is form-only. Roadmap §7.3 called for a drag-select grid. Ship the grid before real tutors onboard.
- Materials section has add + delete but no reorder despite `order_index` in schema.
- Profile section is one big form. Specialties/certs use naive comma-splits; students expect a tag chip input.
- No "my courses" CRUD — courses can only be created via SQL right now. Tutors can't publish new courses at all.

### 3.9 Accessibility

- Skip-link works. Good.
- Star rating buttons on ReviewDialog have `aria-label` but the container doesn't announce "rating group".
- Custom `<button>` elements are used instead of the shadcn `<Button>` for many hand-rolled elements → inconsistent focus rings.
- Color contrast unclear for `text-slate-400` on `bg-white` in some dark-mode combinations — audit with axe-core.

### 3.10 SEO

- `robots.ts` disallows sensible paths. Fine.
- `sitemap.ts` returns only 3 static routes. Should include all tutors + published news + courses.
- No `<meta property="og:image">` fallback — each page needs one; homepage OG is bare.
- No structured data (`Course`, `Person`, `Review` JSON-LD) — leaves rich results on the table.

## 4. Technical / code-quality gaps

### 4.1 Testing (0% coverage)

Nothing exists. For a booking + payment-adjacent flow this is not okay long-term.

**Recommended minimum stack**

- **Unit / integration**: Vitest — the booking overlap logic in `lib/booking.ts` desperately wants tests (timezone edges, back-to-back slots, DST if we ever add it).
- **API contract**: Vitest + `msw` for `/api/*` route handlers.
- **E2E**: Playwright — one smoke path per role (student books → confirms → joins → reviews).

### 4.2 Linting / formatting

- `next lint` runs but no additional rules (a11y, security, imports, promises).
- No Prettier config committed. Formatting drifts.
- No pre-commit hooks (husky + lint-staged).

### 4.3 CI/CD

- No `.github/workflows/*`. Any regression can slip in.
- No preview deploys on PR (Vercel does this out-of-the-box once P10 lands).

### 4.4 Rate limiting

- `/api/livekit/token`, `/api/sessions`, `/api/reviews`, `/api/tutor/profile` all wide open. A logged-in user can spray any of them.
- Add per-IP + per-user rate limits — Upstash Redis or Vercel Edge Middleware handles it.

### 4.5 Input sanitization

- `bio`, `student_notes`, `tutor_notes`, `comment` accept free text via zod but no HTML strip. The `isomorphic-dompurify` package is installed but unused. Either sanitize on the way in or explicitly render as text-only (currently we do render as text, but the field is intended for prose — a student pasting `<script>` sneaks through into other admins' consoles).
- URLs (avatar, intro_video_url, material.url) validated as `.url()` but not against an allowlist — someone can point to `javascript:` in a corner case (zod's url() would catch this, verify).

### 4.6 CSRF

- Mutations rely on Supabase's SameSite=Lax cookies + our own `X-Demo-User` header. That's mostly enough for Chrome/Firefox but a determined attacker with a subdomain can still craft. Add an `X-CSRF-Token` header on all mutations for defense-in-depth.

### 4.7 Security headers / CSP

- `next.config.ts` sets COOP/COEP only for `/game/*` (which we deleted).
- No CSP. No `X-Content-Type-Options`. No `Referrer-Policy`. No `Permissions-Policy`.
- Add a middleware-level header block; Vercel makes this trivial.

### 4.8 Env schema

- Env is read directly via `process.env.SUPABASE_URL || ''`. If a var is missing at runtime, symptoms are cryptic (Supabase throws, session helpers throw, etc.).
- Move to `@t3-oss/env-nextjs` with zod schemas — you get typed env + fail-fast at boot.

### 4.9 Observability

- Zero. `console.error` in a few catches. `apiError` returns a sanitized 500.
- Wire up **Sentry** (free tier fine for MVP) for both client + server. One env var + one wrapper. Massive win.
- Add a lightweight analytics tool. **Plausible** or **Umami** self-hosted. Track: signup, book, join, review, revenue.

### 4.10 Row-Level Security

- Supabase RLS is OFF on every table. All access goes through server routes using `service_role`. If any route ever forgets a check, it's a total-tenant leak.
- Enable RLS with policies that mirror what our route handlers already enforce, then the DB is a second line of defense. Requires touching every table.

## 5. Data / infrastructure gaps

### 5.1 Schema

- `users.timezone` is stored but never consumed. Booking engine hardcodes `UTC+7`. Room page renders times per browser tz. Two sources of truth for tz.
- No `payments` table. When P4b lands, we need it.
- No `notifications` or `email_log`. Same story for reminders + audit.
- No `audit_log` for admin actions (role changes, tutor approvals). GDPR/soft compliance eventually needs this.
- Availability granularity is a `TIME` column pair. Fine now; if you ever want per-slot overrides or recurring exceptions ("Alice off next Tuesday"), you need a `time_off` table.

### 5.2 Indexes

- Covered for the queries we do run. But `getAllSessionsForAdmin` filtered by date range would benefit from `(status, scheduled_at)` composite.
- No `pg_stat_statements` review yet.

### 5.3 Pagination

- `getAllUsers`, `getAllSessionsForAdmin`, `getApprovedTutors` return every row. Add `?limit=&cursor=` to APIs and stitch through UI.

### 5.4 Backups / DR

- Supabase auto-daily backup is fine on their side. No offsite copy. No restore drill documented.

### 5.5 LiveKit prod

- `docker/livekit.yaml` is dev config. Prod needs:
  - Real 32+-char HMAC secret rotated out of git
  - `use_external_ip: true`
  - TURN over TCP fallback (`turn.tcp_port`) explicitly for VN mobile carriers that block UDP
  - Public webhook secret + `NEXT_PUBLIC_LIVEKIT_WS_URL=wss://…`

### 5.6 Docker prod compose

- Missing `caddy` service, no `Caddyfile`, no volume mount for Let's Encrypt cert cache.

## 6. Proposed upgrade roadmap (P11 → P17)

Phases below assume P9 + P10 (docker prod + deploy) have shipped as originally planned. They stack on top; each is 1–3 days of focused work.

### P11 — Design system overhaul (1 day)

1. Recolor: forest-green → indigo brand, metallic-gold → amber accent.
2. Drop KR fonts from `layout.tsx` preload.
3. Typography scale: h1/h2/h3 documented in globals.css.
4. Rename Tailwind tokens (`forest-green` → `brand`, etc.) — bulk find-replace across 48 files.
5. Update `manifest.ts` theme_color + `layout.tsx` viewport meta.
6. Kill emoji icons in home category grid → Lucide.
7. Adjust dark-mode surface to sit better against indigo primary.

### P12 — Quality gates (2–3 days)

1. Add Vitest + a starter unit test set for `lib/booking.ts`, `lib/schemas/*`.
2. Add Playwright + one smoke test per role.
3. Add `eslint-plugin-jsx-a11y`, `eslint-plugin-security`, `eslint-plugin-import`.
4. Add Prettier config + `husky` + `lint-staged` pre-commit.
5. Add GitHub Actions: `ci.yml` running `typecheck` + `lint` + `test` + `build` on every PR.

### P13 — Security hardening (2 days)

1. Rate-limit middleware (Upstash Redis; free tier).
2. CSP + security headers via `next.config.ts`.
3. `@t3-oss/env-nextjs` for typed env + fail-fast.
4. HTML sanitization on bios/comments (`isomorphic-dompurify`).
5. CSRF token on mutation routes.
6. Enable Supabase RLS with policies mirroring server checks.
7. Rotate all secrets currently in this chat (Supabase publishable + service_role + PAT).

### P14 — Observability + notifications (2 days)

1. Sentry wired for both client + server.
2. Plausible self-hosted for analytics.
3. Resend for transactional email:
   - Booking confirmation → student + tutor
   - Reminders T-24h + T-1h (Vercel Cron job)
   - Session completed → student prompted to review
4. `notifications` + `email_log` tables in Supabase; retry on transient failures.

### P15 — Realtime + performance (2 days)

1. Supabase Realtime subscription: admin/tutor dashboards live-update on session status changes.
2. Pagination on `getAllUsers`, `getAllSessionsForAdmin`, `getApprovedTutors`.
3. Compose `getSessionListForUser` and `getAllSessionsForAdmin` — they share denormalization code.
4. Image CDN: proxy Unsplash through `next/image` (already partially there) or self-host banner images.
5. `pg_stat_statements` review; add missing indexes if any query blocks a bar.

### P16 — Product features batch 1 (3–4 days)

1. **Timezone**: respect `users.timezone`; render availability slots in tutor tz + show student's tz label.
2. **Tutor courses CRUD**: tutor can create + publish courses without SQL.
3. **Availability drag-grid**: replace form with visual weekly grid drag-select.
4. **Reschedule UI**: student-facing dialog on `SessionCard`.
5. **Materials reorder**: expose `order_index` with drag handle.
6. **In-room chat toggle**: already comes with LiveKit prefab; wire feedback modal on disconnect.
7. **Home testimonials**: pull recent 5-star reviews.

### P17 — Product features batch 2 (post-MVP)

Held for when P11–P16 are done + real users exist:

- Payments (VNPay / Stripe)
- Group classes (1 tutor + N students)
- Recording via LiveKit Egress
- Whiteboard (Excalidraw embed)
- Mobile app (React Native)
- AI post-session pronunciation feedback
- Referral / affiliate program
